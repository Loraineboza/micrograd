# Micrograd

## Назначение проекта

Этот проект реализует небольшой движок автоматического дифференцирования на NumPy для обучения и исследования вычислительного графа. В отличие от PyTorch, здесь используется минимальный API на основе `Tensor`, который отслеживает зависимости между узлами и выполняет обратное распространение градиентов вручную.

## Вычислительный граф и обратный проход

Каждый узел вычислительного графа хранит:
- `data` — числовое значение массива или скаляра;
- `grad` — градиент относительно выхода;
- `parents` — родительские узлы, от которых зависит текущая операция;
- `_backward` — функция вычисления градиентов для этой операции;
- `requires_grad` — признак, участвует ли тензор в вычислении градиентов.

После вычисления целевой функции вызывается `loss.backward()`. Внутри используется обход графа в топологическом порядке, затем обратный проход по узлам от выхода к входам. Для каждого родителя применяется правило дифференцирования и значения суммируются через `+=` для корректного накопления градиентов при повторном использовании одного и того же узла.

## Поддерживаемые операции и ограничения

Поддерживаются:
- поэлементное сложение и вычитание;
- поэлементное умножение;
- матричное умножение для двумерных массивов;
- `sum()` и `mean()` с `axis` и `keepdims`;
- операции `exp`, `log`, `sigmoid`, `tanh`, `relu`, `clip`;
- broadcasting при сложении матрицы и вектора смещения;
- простые линейные слои через `Linear` и `MLP`.

Ограничения:
- `__matmul__` поддерживает только двумерные массивы; неподдерживаемые формы завершаются ясной ошибкой `ValueError`;
- для повторного использования одного и того же тензора в нескольких ветвях графа используется накопление градиентов;
- для сброса накопленных градиентов используется `tensor.zero_grad()`;
- алгоритм не является полной заменой PyTorch и не п��ддерживает весь набор операций и оптимизаций полного DL-фреймворка.

## Накопление градиентов и broadcasting

В вычислительном графе один и тот же узел может использоваться в нескольких ветвях. Поэтому в обратном проходе применяются не перезапись, а суммирование:

- `self.grad += ...`
- `other.grad += ...`

Это позволяет корректно учитывать вклад нескольких путей в итоговый градиент.

Для broadcasting используется приведение градиента обратно к исходной форме исходного тензора через суммирование по тем осям, которые были введены broadcasting. Например, при сложении массива `(8, 2)` с вектором `(2,)` градиент по вектору вычисляется как сумма по первой оси.

## Проверочный пример X @ W + b

Ниже приведён обязательный пример, который должен быть воспроизводимым и работать с собственным autodiff:

```python
rng = np.random.default_rng(0)
X = rng.standard_normal((8, 3), dtype=np.float64)
W = rng.standard_normal((3, 2), dtype=np.float64)
b = np.array([0.5, -0.5], dtype=np.float64)
Y = rng.standard_normal((8, 2), dtype=np.float64)

X_t = Tensor(X, requires_grad=False, name="X")
W_t = Tensor(W, requires_grad=True, name="W")
b_t = Tensor(b, requires_grad=True, name="b")
Y_t = Tensor(Y, requires_grad=False, name="Y")

P = X_t @ W_t + b_t
L = ((P - Y_t) ** 2).mean()
L.backward()
```

В результате вычисляются:
- `P.shape == (8, 2)`;
- `loss = mean((P - Y) ** 2)`;
- `grad_W`, `grad_b` — градиенты по собственному механизму autodiff.

## Известные ограничения

- Реализация не является полной заменой PyTorch, JAX, TensorFlow и не поддерживает весь набор DL-операций.
- Для повторного вызова `backward()` используется семантика накопления градиентов; чтобы сбросить градиенты, вызовите `zero_grad()`.
- Вычисление градиента для массивов с большим количеством broadcasting-операций зависит от корректного суммирования по оси; все неподдерживаемые формы должны явно падать с `ValueError`.

## Ошибка и её обнаружение

Этот пункт оставлен для заполнения пользователем, если в проектной истории нет конкретной реальной ошибки. В текущем состоянии проекта можно отметить, что любой реальный дефект должен обнаруживаться через численный gradcheck: если аналитический градиент расходится с конечной разностью по критерию

`abs(g - g_ref) <= 1e-6 + 1e-4 * abs(g_ref)`

то это свидетельствует о неверной формуле обратного прохода или о неправильной обработке broadcasting.

# Дополнительные тесты для `micrograd`

Этот пакет содержит тесты для проверки математической корректности autograd-движка.
Он не переписывает реализацию `micrograd` и не меняет исходные модули.

## Что проверяется

- градиенты поэлементных `+` и `*`;
- градиенты матричного умножения;
- broadcasting bias `b` формы `(2,)` для выражения `X @ W + b`;
- численная проверка градиентов `W` и `b` центральными конечными разностями;
- градиент `sum(x*x + x)`;
- накопление градиентов в сходящихся ветвях графа;
- поведение при повторном `backward()`;
- максимальная абсолютная ошибка gradcheck.

## Перед запуском

Тесты ожидают, что публичный API находится в `micrograd.autograd` и содержит класс `Tensor`.

## Критерий gradcheck

Для каждого элемента сравниваются аналитический градиент и центральная конечная разность:

`g_num = (L(x + eps) - L(x - eps)) / (2 * eps)`

Используется `float64`, `eps=1e-6` и допуск:

`abs(g - g_num) <= 1e-6 + 1e-4 * abs(g_num)`

Эти тесты дополняют существующие тесты проекта. Если в репозитории уже есть аналогичные проверки,
объедините их вместо дублирования. Тест повторного `backward()` намеренно допускает reset- или
accumulate-семантику, поскольку это решение реализации должно быть явно задокументировано.
